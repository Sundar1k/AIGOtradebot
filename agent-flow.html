How the Agent Works — Operating Model

two loops: interactive (you ↔ agent ↔ tools) and autonomous (crons ↔ services ↔ bot) · the agent builds, maintains, and reports on the stack — it doesn't babysit it

Interactive loop

  • You message → agent loads context (memory, skills, doctrine)
  • Plans → acts (tools) → verifies (evidence) → reports (CLI/files)
  • Learns → memory + skill patches → next session starts smarter
  • Approval gates for destructive/GPU/account-touching work

Autonomous stack

  • Crons run without the agent: watchdog (guardian), regime, doctor
  • Services: autotrade (breakers+heartbeat), veto (7B), ai-ctx
  • Bot trades the eval per the master-flow funnel, doctrine enforced
  • Guardian closes positions if the bot dies — no unmanaged overnights

The connection

  • Agent BUILDS/maintains the stack; it doesn't babysit it
  • Agent READS state files for reports ("what happened?")
  • Agent removes noise (7 crons today) and patches the skill
  • Doctrine hardcoded at every layer the agent touches
